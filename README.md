## NVMe 快在哪，以及你可能根本不需要它

NVMe 相对 SATA SSD 的提升集中在两个指标：顺序读写的带宽，和高并发下的随机读写。数字大致是：读速 3,500–7,000 MB/s，对 SATA 的 550 MB/s；延迟从 50–60 微秒降到 10–20 微秒。落到日常操作上，拉镜像能快 2–3 倍，git clone 能省下四到六成时间。

真正吃这项性能的是随机读写密集的负载：PostgreSQL、MySQL、Redis 这类数据库，CI 构建机，容器宿主机。这类场景里，NVMe 的钱花得值。

反过来，下面这些场景基本无感：静态博客、文件归档、跑定时脚本。为它们买 NVMe 纯属浪费，$2 档的 SATA SSD 套餐（比如 RackNerd 的 $1.99/月款）就够用。

还有一层容易被忽略：动辄几十万 IOPS 是裸盘成绩。你买到手的 VPS 处在虚拟化环境里，磁盘和别的租户共享，实际能分到多少，取决于商家有没有超售。所以光看套餐页没用，得自己验。

## 宣传页写着 NVMe，跑起来未必是：5 分钟自查

判断商家给的是不是真 NVMe，唯一可靠的办法是拿到机器后跑一次 fio，看 4K 随机读写成绩——页面写"SSD"时，背后可能是 NVMe，可能是 SATA SSD，甚至是机械盘加 SSD 缓存。

一项针对 12 家商家入门套餐的第三方实测很能说明问题：同样的"NVMe"，超售严重的低价商家只跑出 6,000 IOPS，做得最好的 UpCloud MaxIOPS 跑出 100,000+，尾延迟 p99 不到 1 毫秒。那套测评的淘汰线值得借用：中位数读 IOPS 低于 15,000 的直接排除——低于这条线，"NVMe"就只是个营销词。


fio --rw=randread --bs=4k --iodepth=32 --numjobs=4 --runtime=300 --time_based --direct=1


多数商家按小时计费，开机花几毛钱跑 5 分钟再决定，不合适退掉就行。看结果时留意尾延迟：平均 5 万 IOPS 但 p99 冲到几十毫秒的机器，真实体验比稳定 3 万的更差。
